# Beauty Center ERD v1

This is a single-tenant PostgreSQL schema for operational data only. Internal and foreign keys are `bigint`; main externally-addressable entities also expose a unique `uuid` generated by `pgcrypto` (`gen_random_uuid()`). All actual date-times use `timestamp with time zone` and must be stored in UTC. PostgreSQL enums are deliberately not used.

## Relationships and deletion rules

| Parent | Child | Relationship | Delete rule |
| --- | --- | --- | --- |
| `service_categories` | `services` | A category has many services. | Restrict |
| `employees` / `services` | `employee_services` | Capability join table with a composite primary key. | Cascade from either parent |
| `employees` | `employee_working_hours` | An employee has zero or more daily working intervals. | Cascade |
| `employees` | `employee_unavailability` | An employee has breaks, leave, and manual blocks. | Cascade |
| `customers` | `appointments` | A customer owns appointments. | Restrict |
| `employees` | `appointments` | An employee performs appointments. | Restrict |
| `appointments` / `services` | `appointment_services` | Appointment-service snapshot join table. | Cascade from appointment; restrict from service |

`employees` and `customers` support soft deletion. Appointments snapshot the booked price and duration in `appointment_services`, so later edits to a service do not rewrite history.

## Required indexes

| Index / constraint | Query or integrity rule served |
| --- | --- |
| Unique UUIDs, category name, customer phone, and nullable non-null emails/phones | Stable external references and duplicate prevention. PostgreSQL unique constraints allow multiple `NULL`s. |
| `services_active_category_name_idx (service_category_id, name) WHERE is_active = true` | Lists active services in a selected category, ordered/filterable by name. |
| `employee_services` primary key `(employee_id, service_id)` | Loads an employee's capabilities and prevents duplicate assignments. |
| `employee_services_service_employee_idx (service_id, employee_id)` | Selects employees qualified for one service. |
| `employee_working_hours_exact_unique` | Rejects duplicate intervals for one employee and weekday. |
| `employee_working_hours_employee_weekday_start_idx (employee_id, weekday, start_time)` | Loads the schedule intervals for an employee/day. |
| `employee_unavailability_employee_start_idx (employee_id, start_at)` | Checks blocks affecting an employee around a requested time. |
| `appointments_employee_active_start_idx (employee_id, start_at) WHERE status IN ('pending', 'confirmed')` | Checks active appointments for one employee. |
| `appointments_active_start_idx (start_at) WHERE status IN ('pending', 'confirmed')` | Shows active appointments in the booking calendar. |
| `appointments_customer_start_idx (customer_id, start_at DESC)` | Shows a customer's appointment history. |
| `appointments_no_active_employee_overlap` exclusion constraint | Rejects overlaps for a single employee while either appointment is pending or confirmed. The half-open range `[)` permits adjacent appointments. |
| `appointment_services` primary key `(appointment_id, service_id)` | Loads services attached to an appointment and prevents duplicate service rows. |

## Deferred indexes

The following are intentionally omitted in v1 until measured product use justifies their write cost: full-text search, JSONB GIN, standalone indexes on `status`, `is_active`, and `created_at`. No name, loyalty-point, or generic foreign-key indexes are added beyond the listed MVP queries.

## Booking implementation note

The booking service is intentionally out of scope. When it is built, it must run inside `DB::transaction()`, lock the employee or relevant appointment records using `lockForUpdate()`, then validate active-appointment overlap, working hours, and `employee_unavailability`. The exclusion constraint remains the final database-level protection against concurrent active appointments.
